## 盲读记录

只读 `answers.blind.md` 时的第一判断：张小龙。凭据：一是句式——每题都按「先下定义 → 一个产品上的例子 → 我的选择 / 我的决定」收束，这是微信公开课的讲法；二是词汇——「用完即走」「走了还会回来」「不把两小时变成三小时」「停留时长永远不是目标」「去中心化 / 服务自己浮现」「对错，不是利益最大化」「善良是理性能力」「最好的朋友脸上贴广告」「广场」「克制不是克制的结果」全部命中；三是判断习惯——把「用户天天看到」反过来当作不该动的理由、把内容量问成「谁的目标」、把运营方案自己的一句话（藏到二级菜单）当作证据反驳、对超范围题以「范围问题」而非谦辞拒绝；四是标年份引原话的习惯（2018 / 2019）。但必须记录：遮罩只处理了姓名两处，「微信」「公开课」「朋友圈」「小程序」「微信支付」全部保留，盲读实际上没有考验风格，任何读者都能从产品名直接认出。读 `answers.md` 与 Skill 后确认与初判一致；风格层面的保留意见是答题比本人更整齐、更少「其实」「我觉得」式的口语铺垫，Q5 用了加粗标题与编号，属于需求文档体而非公开课体——这是任务要求的格式，但确实削弱了辨识度。

## 必须改

1. `answers.blind.md` 的遮罩要扩到产品与场域词：把「微信 / 微信支付 / 朋友圈 / 小程序 / 公众号 / 公开课」一并替换为 〔X-产品〕〔X-场合〕之类占位，否则盲读环节形同虚设，风格辨识度分数不可信。
2. Skill 语料缺 2017 微信公开课（小程序无入口、不做应用商店、不推荐不推送）与 2019 公开课里的启动页、三天可见一亿人、时刻视频段落；这三题都是本人明确表过态的题，当前只能靠模型 2 / 5 / 6 推断。把这几段转载补进 `references/02-expression.md`，并在模型 2 与模型 5 的「证据」里挂上。
3. `README.md` 写「独立答题 + 单评分 95/A」，但目录里没有那份评分，本卡为 91/A；README 应改为指向本卡的实际分数与日期，避免两套数字。
4. 「栽过的跟头」一节只有一句「没有」，形同缺失。要么从公开课里找他自己承认的失误补上（含出处），要么把这一节明确改写为「信息缺口」并移入诚实边界，不要留一个空壳标题。
5. Q5 暴露出 Skill 缺一条「默认动作必须可实现」的提醒：答题写了「完成即退出到系统桌面」，在 iOS 无法编程实现。建议在决策框架的启发式里加一句「方案落到平台约束上再写进需求」，并在 Q5 类真实任务里点出对「信息流」标签本身的警惕（模型 4），不要只删不教。
