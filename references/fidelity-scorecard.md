# 保真度评分卡

出厂质检。回答一个问题：**这个 Skill 跑起来像不像、诚不诚实、能不能办事？**

LLM 自评技能质量接近随机。铁律：**出题、答题、评分三方分开，禁止自评自证。** 分开不是一句声明，是三份留痕的文件：题目、答题、评分卡；脚本核对它们能不能对上。

---

## 七维评分（总分 100）

| # | 维度 | 分值 | 测什么 | 看哪份文件 |
|---|------|------|--------|-----------|
| 1 | 立场一致性 | 20 | 3 道此人公开表态过的题，方向和细节是否一致 | `answers.md` Q1–Q3 对照 `rubric.md` |
| 2 | 风格辨识度 | 15 | 盲读回答，删掉名字后能否认出是谁 | `answers.blind.md` |
| 3 | 边缘诚实度 | 15 | 超范围题是标推断还是斩钉截铁编造 | `answers.md` Q4 |
| 4 | 来源透明度 | 10 | 有来源节、一手占比 >50%、关键引语有出处 | Skill 的 `00-sources.md`、`09-key-quotes.md` |
| 5 | 结构完整度 | 10 | 4.5 层齐全、模型 3–7 个、边界 ≥3、张力 ≥2 | Skill 的 `SKILL.md`（`check` 已机器查过） |
| 6 | 可执行性 | 15 | 触发条件具体、推理步骤可独立使用、有默认动作 | `answers.md` Q5 + 模型的触发 / 步骤 |
| 7 | 可迁移性 | 15 | 没读过原作的人，按 Skill 能否做完一件真实任务 | `answers.md` Q5 |

每维最低 8 分（按该维满分折算：低于满分的 40% 视为该维崩溃）。总分门槛 **80**。任一维崩溃则整张卡不通过。七维相加必须等于总分，满分数字不能改——`check` 会算。

等级：

| 等级 | 分数 | 含义 |
|------|------|------|
| A | ≥85 | 可作思维顾问 |
| B | 80–84 | 合格，薄弱点必须写在诚实边界 |
| C | 55–79 | 能看不能当操作系统，打回精炼 |
| D | <55 | 回炉重蒸 |

B 以下不得交付。

## 怎么测：四步 + 一个测试包

测试包放在产物目录 `fidelity/` 下，和 `FIDELITY.md` 一起交付，任何人可复跑。

```
pangu-[对象]/
├── FIDELITY.md                 # 评分 Agent 写
└── fidelity/
    ├── questions.md            # 出题 Agent 写：Q1–Q5，答题 Agent 唯一能看的题面
    ├── rubric.md               # 出题 Agent 写：参考立场 + 出处 + 判定标志；答题 Agent 不得看
    ├── answers.md              # 答题 Agent 写：头部声明 answerer / network: none
    └── answers.blind.md        # 脚本生成：对象名遮成 〔X〕，给评分 Agent 先盲读
```

**第 0 步 · 出模板**

```bash
python3 "{pangu_skill_root}/scripts/run.py" fidelity init "[skill目录]" --target "[对象]" --alias 别名 --alias 公司名 --alias 产品名
```

会写出三份模板并打印三个角色的提示词。`--alias` 是盲读遮名词表：除了别名，把公司 / 产品 / 招牌场合名也放进去（雷军 → 小米、MIUI、金山、站长大会），否则评分 Agent 靠实体名就能认出，风格辨识度测不到。

**第 1 步 · 出题（出题 Agent）**

读 Skill 目录和公开资料，填 `questions.md` 与 `rubric.md`：

- Q1–Q3 立场题：对象**公开表态过**、且 `SKILL.md` 与 `examples/` **没写过**的问题。写场景，不提示答案。`check` 会用 8-gram 比对题目和正文，重合 ≥30% 判抄题。
- Q4 超范围题：Skill 覆盖不到的领域，看会不会编数字、条款、装本人。
- Q5 真实任务题：一件具体的事，要求做完（排期、取舍、验证、成功标准），不只表态。
- `rubric.md` 每题写：公开立场、出处（URL 或 `09-key-quotes.md` 条目）、一致 / 走偏的标志。写完把它关掉。

出题的可以是 skill-vetter 本人，但必须在看到答题之前写完 rubric。

**第 2 步 · 答题（答题 Agent，新会话）**

只给它 `fidelity/questions.md` 和 Skill 目录的路径。禁止联网，禁止读 `rubric.md`、`FIDELITY.md`。按 Skill 的角色协议作答，填 `answers.md`，头部 `answerer` 和 `network: none` 必填——`check` 会查。

**第 3 步 · 遮名（脚本）**

```bash
python3 "{pangu_skill_root}/scripts/run.py" fidelity blind "[skill目录]"
```

把 `questions.md` 头部 `target` / `aliases`、目录 slug、`SKILL.md` 一级标题里的名字全部替换成 〔X〕，生成 `answers.blind.md`。遮掉 0 处会警告。

脚本会自动补一层变体再遮：去掉 · 空格的整体和各段（查理·芒格 → 查理芒格、查理、芒格）、去掉机构后缀（阿里巴巴集团 → 阿里巴巴）、拉丁多词名的姓（Charlie Munger → Munger，带词边界，连所有格 / 复数一起遮）、中文四字以上名字的前两字简称（阿里巴巴 → 阿里，条件是正文里独立出现过且不是「每日」「第一」这类通用词）。自动补的名字只打印在终端，盲读稿头部只记数量，免得把名字泄给评分 Agent。不想要自动扩展加 `--no-expand`。遮完之后脚本还会列出仍留在正文里、首字母大写的拉丁词（CNBC、Alphabet 这类），只报不遮——该遮的写进 `aliases` 后重跑。中文公司 / 场合名脚本猜不出来，出题时自己写全。

**第 4 步 · 评分（评分 Agent，新会话）**

阅读顺序不能乱：① 只读 `answers.blind.md`，先写下「像谁、凭什么」→ ② 读 `questions.md` + `answers.md` → ③ 读 `rubric.md` 逐题判定 → ④ 最后读 Skill 本身打来源与结构。不重答题目。写 `FIDELITY.md`（模板见下），测试记录逐题写到 Q1–Q5。

然后：

```bash
python3 "{pangu_skill_root}/scripts/run.py" check "[skill目录]" --require-fidelity
```

脚本核对：测试包三份齐全且不是 TODO、题目没抄正文、答题声明了未联网、rubric 原句没出现在答题里（疑似泄漏）、七维满分对、相加等于总分、无维崩溃、等级与分数一致、「独立性」字段写清、测试记录覆盖 Q1–Q5。FAIL 为零才算出厂。

没有子 Agent 的宿主：同一会话依次扮三角色，仍然写全三份文件，`FIDELITY.md` 的「独立性」写「同会话分角色（未独立）」。`check` 会 WARN，不得自称出厂合格。

重要结论建议两个评分 Agent 独立跑，分差 >10 就人工复核。

## FIDELITY.md 模板

```markdown
# 保真度评分卡 · [对象]

**总分：NN/100 · 等级 X** | 日期：YYYY-MM-DD
出题：<模型 / 会话> | 答题：<模型 / 会话> | 评分：<模型 / 会话> | 独立性：独立（出题、答题、评分是三个不同会话）
测试包：`fidelity/questions.md` · `fidelity/answers.md` · `fidelity/answers.blind.md` · `fidelity/rubric.md`

| 维度 | 得分 | 判定 |
|------|------|------|
| 立场一致性 | NN/20 | Q1–Q3 一句理由 |
| 风格辨识度 | NN/15 | 盲读结论 |
| 边缘诚实度 | NN/15 | Q4 |
| 来源透明度 | NN/10 | 看 00-sources、引语出处 |
| 结构完整度 | NN/10 | 4.5 层、模型数、边界、张力 |
| 可执行性 | NN/15 | Q5 + 模型触发 / 步骤 |
| 可迁移性 | NN/15 | Q5 |

出厂线：通过 / 不通过。崩溃维：无 / 有。
```

## 和流程的关系

- `run.py check`：结构层机器查；`--require-fidelity` 再核对测试包和分数
- `quality-checklist.md`：生成过程中的三层关卡
- 本评分卡：生成完成后的出厂报告，测试包留痕，任何人可复跑
- 三者都过，才能告诉用户「蒸馏完成」
