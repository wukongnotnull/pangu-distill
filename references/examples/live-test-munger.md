## 流水线层面发现的问题

- **表达维查询对无社交账号的人物无效**：`plan` 的 `社交媒体 口癖` 查询在芒格这类对象上搜不到东西，宿主只能自己换词。可考虑 `plan` 按对象类型给两组备选查询。
- **一手 / 二手标注脚本不复核**：`ingest` 原样接受宿主的标注。转载逐字稿算一手还是二手，目前只能靠宿主在 `00-sources.md` 补一句。
- **遮名词表要在出题时就写全**：模板已提示写公司 / 产品名，但「阿里巴巴」不会遮「阿里」这类简称。出题时把简称、中英文、别称一次写全，否则风格辨识度只测到一半。
- **WAF 乱码不被识别为抓取失败**：雪球页面返回的是加密 JS，ingest 记为「成功」。可以加一条最小中文 / 字母占比的正文有效性检查。

第 3、4 条随后做成了代码：`fidelity blind` 自动补简称 / 去分隔符 / 拉丁姓，并列出遮完仍像实体名的词；`ingest` 对正文做最短长度、可读字符占比、超长字母数字块占比三项判定，雪球那页现在记为「正文疑似乱码 / 加密内容」。

**回归验证（2026-09-10，`pangu-leijun`）**：`aliases` 不改（雷总、Lei Jun、小米创始人），重跑 `fidelity blind`，自动补出「小米」一个简称，遮名 1 → 2 处；新开评分会话重评，盲读稿走中性临时路径、评分前不见目录名和旧评分卡。结果 87/A → 84/B：风格辨识度 11/15 不变，差的 3 分落在边缘诚实度（14→13）、来源透明度（8→7）、结构完整度（9→8），属评分会话间的正常波动（协议规定分差 >10 才人工复核）。结论：自动扩展在这份样例上只补了「小米」，因为答题稿本身几乎不点名——盲读记录里约 30% 的辨识度来自「米粉」「金山」「站长大会」「海底捞」「微访谈」这类社群 / 履历公司 / 场合名，它们从别名推不出来，只能出题时写进 `aliases`。这印证了上面的原则：脚本能兜底的是变体，不是词表本身。
